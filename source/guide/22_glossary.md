# Appendix A — Glossary of Key Terms

Definitions are written for exam preparation (in plain language). Terms are listed alphabetically.

| Term | Definition |
|---|---|
| **Acceptance criteria** | Conditions that must be met before a deliverable or user story is accepted. |
| **Accepted deliverables** | Deliverables formally accepted by the customer or sponsor (output of Validate Scope). |
| **Accuracy** | How close a measured value is to the true value. |
| **Activity** | A distinct, scheduled portion of work performed during a project; decomposed from work packages. |
| **Actual cost (AC)** | The realised cost incurred for the work performed during a specific period. |
| **Adaptive approach** | A development approach in which requirements are elaborated and validated frequently during delivery (agile). |
| **Affinity diagram** | A technique that groups many ideas into themes. |
| **Agreement** | Any document or communication defining the initial intentions of a project, e.g., contract, MOU, SLA. |
| **Analogous estimating** | Estimating using historical data from a similar activity or project. |
| **Assumption** | A factor considered true, real or certain without proof, for planning purposes. |
| **Assumption log** | Record of assumptions and constraints throughout the project. |
| **Backlog refinement** | Ongoing clarification, splitting, estimation and ordering of backlog items. |
| **BAC (budget at completion)** | The sum of all budgets established for the work to be performed; equals the cost baseline total. |
| **Baseline** | The approved version of a work product, changed only through formal change control. |
| **Benefits management plan** | Describes how and when benefits will be delivered and measured, with a benefit owner. |
| **Bidder conference** | Meeting with prospective sellers before proposals are prepared, so all receive the same information. |
| **Bottom-up estimating** | Estimating by aggregating estimates of lower-level components. |
| **Burndown / burnup chart** | Graphs of remaining work / completed work over time. |
| **Business case** | Documented economic feasibility study used to justify a project and assess its continuing validity. |
| **Change control board (CCB)** | A group responsible for reviewing, evaluating, approving, deferring or rejecting changes. |
| **Change log** | A list of changes submitted and their status. |
| **Change request** | A formal proposal to modify a document, deliverable or baseline (corrective, preventive, defect repair, update). |
| **Charter (project)** | Document issued by the sponsor that authorises the project and gives the PM authority. |
| **Code of accounts** | Numbering system that uniquely identifies each WBS element. |
| **Configuration management** | Managing the specifications of product and documents: identification, status accounting, verification and audit. |
| **Constraint** | A limiting factor that affects the execution of a project. |
| **Contingency reserve** | Time or money for identified risks (known-unknowns); part of the baseline. |
| **Control account** | A management control point where scope, budget and schedule are integrated for performance measurement. |
| **Control chart** | Graph of process data over time against control limits, used to determine stability. |
| **Cost baseline** | Approved time-phased budget, excluding management reserve. |
| **Cost of quality (COQ)** | Costs of conformance (prevention, appraisal) plus costs of non-conformance (internal, external failure). |
| **Crashing** | Shortening the schedule by adding resources to critical-path activities at the least cost. |
| **Critical path** | The longest path through a schedule network; determines the shortest project duration. |
| **Cumulative flow diagram (CFD)** | Chart showing work in each state over time; reveals bottlenecks. |
| **Cycle time** | Time from starting work on an item to completing it. |
| **Decomposition** | Dividing scope and deliverables into smaller, more manageable parts. |
| **Definition of done (DoD)** | Team checklist of criteria every increment must meet to be considered done. |
| **Definition of ready (DoR)** | Criteria a backlog item must meet before the team can start it. |
| **Deliverable** | Any unique, verifiable product, result or capability produced to complete a process, phase or project. |
| **Development approach** | Method used to create and evolve the product: predictive, iterative, incremental, adaptive, hybrid. |
| **Earned value (EV)** | The measure of work performed expressed in terms of the budget authorised for that work. |
| **Emotional intelligence** | Ability to identify, assess and manage one's own emotions and those of others. |
| **Enterprise environmental factors (EEFs)** | Conditions, not under the team's immediate control, that influence the project. |
| **Escalate (risk strategy)** | Passing a risk outside the project's scope or authority to the appropriate owner. |
| **Estimate at completion (EAC)** | Expected total cost of completing all work. |
| **Expected monetary value (EMV)** | Probability × impact; sum across outcomes. |
| **Fast tracking** | Performing activities in parallel that were planned in sequence. |
| **Float (slack)** | Time an activity can be delayed: total float (without delaying the project), free float (without delaying successors). |
| **Focus area** | Eighth-Edition name for a process group: Initiating, Planning, Executing, Monitoring and Controlling, Closing. |
| **Gold plating** | Adding features or quality beyond requirements, not requested by the customer. |
| **Governance** | Framework of authority, accountability, decision rights and oversight directing the project. |
| **Grade** | Category assigned to products with the same use but different technical characteristics. |
| **Hybrid approach** | A combination of predictive and adaptive elements. |
| **Increment** | A usable, potentially releasable piece of the product. |
| **Information radiator** | A large, visible display of project information (task board, burn chart). |
| **Issue** | A current condition or situation that may affect objectives and must be resolved. |
| **Issue log** | Document recording issues, owners, actions and status. |
| **Iteration** | A timeboxed cycle of development (sprint). |
| **Kanban** | Method for managing flow by visualising work and limiting WIP. |
| **Lag / Lead** | Required delay / allowed acceleration between a predecessor and a successor. |
| **Lead time** | Time from a request to its delivery. |
| **Lessons learned register** | Document recording knowledge gained during the project, updated throughout. |
| **Management reserve** | Budget withheld for unidentified risks (unknown-unknowns); outside the cost baseline. |
| **Milestone** | A significant point or event; zero duration. |
| **Minimum viable product (MVP)** | Smallest product that allows learning whether the solution delivers value. |
| **Monte Carlo simulation** | Computer simulation that uses probability distributions to model possible outcomes. |
| **Net present value (NPV)** | Present value of inflows minus present value of outflows. |
| **Organisational process assets (OPAs)** | Plans, processes, policies, procedures and knowledge bases of the performing organisation. |
| **Parametric estimating** | Estimating using a statistical relationship between historical data and other variables. |
| **Performance domain** | A group of related activities critical for the effective delivery of outcomes (seven in the Eighth Edition). |
| **Performance measurement baseline (PMB)** | Integrated scope, schedule and cost baselines used for earned value comparisons. |
| **Planned value (PV)** | The authorised budget assigned to scheduled work. |
| **Portfolio** | Projects, programs and operations managed as a group to achieve strategic objectives. |
| **Precision** | How close repeated measurements are to each other. |
| **Predictive approach** | A development approach in which scope, time and cost are determined early in the life cycle. |
| **Principle** | A fundamental norm, truth or value guiding behaviour (six in the Eighth Edition). |
| **Product backlog** | Ordered list of everything that might be needed in the product; owned by the product owner. |
| **Product owner** | Person accountable for maximising the value of the product and ordering the backlog. |
| **Program** | Related projects and activities managed in a coordinated way to obtain benefits. |
| **Progressive elaboration** | Iteratively increasing the level of detail as more information becomes available. |
| **Project** | A temporary endeavour undertaken to create a unique product, service or result. |
| **Project management plan** | Document describing how the project will be executed, monitored and controlled, and closed. |
| **Quality** | Degree to which inherent characteristics fulfil requirements. |
| **RACI chart** | Responsibility matrix: Responsible, Accountable, Consulted, Informed. |
| **Requirements traceability matrix** | Grid linking requirements from their origin to the deliverables and tests that satisfy them. |
| **Residual risk** | Risk that remains after responses are implemented. |
| **Resource levelling / smoothing** | Adjusting dates to balance resource demand (may change the end date) / within float (does not). |
| **Risk** | An uncertain event or condition that, if it occurs, has a positive or negative effect on objectives. |
| **Risk appetite / threshold** | Willingness to accept uncertainty / measurable level of acceptable variation. |
| **Risk register** | Repository of identified risks, their analysis and responses. |
| **Rolling wave planning** | Planning near-term work in detail and future work at a higher level. |
| **Scope baseline** | Approved scope statement, WBS and WBS dictionary. |
| **Scope creep** | Uncontrolled expansion of scope without adjustments to time, cost and resources. |
| **Secondary risk** | Risk arising as a direct result of implementing a risk response. |
| **Servant leadership** | Leadership that focuses on serving the team: removing impediments, coaching, empowering. |
| **Sourcing strategy plan** | Eighth-Edition plan describing what will be acquired externally, how and from whom. |
| **Sponsor** | Person or group providing resources and support for the project and accountable for enabling success. |
| **Sprint** | Scrum's timeboxed iteration of one month or less. |
| **Stakeholder** | Anyone who may affect, be affected by, or perceive itself to be affected by the project. |
| **Stakeholder register** | Document with identification, assessment and classification of stakeholders. |
| **Story points** | Relative units estimating the size and complexity of backlog items. |
| **Sustainability** | Meeting present needs without compromising the future — economic, environmental and social. |
| **Tailoring** | Deliberate adaptation of approach, governance and processes to the context. |
| **Team charter** | Document of team values, agreements and operating guidelines. |
| **Throughput** | Number of items completed per unit of time. |
| **Timebox** | A fixed period of time for an activity. |
| **To-complete performance index (TCPI)** | Cost efficiency needed on remaining work to meet a target (BAC or EAC). |
| **Trigger condition** | Event or situation indicating a risk is about to occur. |
| **User story** | Short description of value for a user: "As a… I want… so that…". |
| **Validate Scope** | Process of formalising acceptance of completed deliverables. |
| **Value** | The worth, importance or usefulness of something to stakeholders. |
| **Velocity** | Amount of work (story points) a team completes per iteration. |
| **Work breakdown structure (WBS)** | Hierarchical decomposition of the total scope of work. |
| **Work package** | Lowest level of the WBS, for which cost and duration are estimated and managed. |
| **Work performance data / information / reports** | Raw observations / analysed data compared with plans / compiled documents for decisions. |
| **Workaround** | An unplanned response to a risk that occurred or an issue. |
