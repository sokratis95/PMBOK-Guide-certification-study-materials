# Chapter 19 — Models, Methods and Artifacts: the Practitioner's Toolbox

**After this chapter you should be able to:**
- distinguish models, methods and artifacts;
- select an appropriate model, method or artifact for a given purpose;
- recognise the purpose of the artifacts most often named in exam questions.

The Seventh Edition introduced the idea of a toolbox of **models, methods and artifacts (MMAs)** and the Eighth Edition keeps it. You do not need to memorise the list — but you must know **what each item is for**, because exam options often name them.

- **Model** — a thinking strategy to explain a process, framework or phenomenon (e.g., Tuckman's ladder).
- **Method** — a means of achieving an outcome, output, result or deliverable (e.g., a SWOT analysis, planning poker).
- **Artifact** — a template, document, output or project deliverable (e.g., the risk register).

## 19.2 Commonly used methods

### Data gathering and analysis

| Method | Purpose |
|---|---|
| **Alternatives analysis** | Evaluate options to choose the best way to do the work |
| **Assumption and constraint analysis** | Check that assumptions and constraints are valid and integrated |
| **Benchmarking** | Compare actual or planned practices with comparable organisations to find ideas and standards |
| **Business justification analysis** — payback, IRR, NPV, ROI, cost-benefit, BCR | Justify or select investments |
| **Check sheet** | Tally data during inspections |
| **Cost of quality** | Balance conformance vs non-conformance costs |
| **Decision tree analysis** | Evaluate alternatives under uncertainty (EMV) |
| **Earned value analysis** | Measure scope, schedule and cost performance |
| **Expected monetary value** | Quantify the value of uncertain outcomes |
| **Forecast** | Predict future performance (EAC, ETC, Monte Carlo) |
| **Influence diagram** | Graph the decisions, uncertainties and outcomes |
| **Life cycle assessment** | Evaluate total environmental impact of a product |
| **Make-or-buy analysis** | Decide whether to produce internally or purchase |
| **Probability and impact matrix** | Prioritise risks |
| **Process analysis** | Find process improvements |
| **Regression analysis** | Examine relationships among variables for forecasting |
| **Reserve analysis** | Evaluate remaining reserves vs remaining risk |
| **Root-cause analysis** | Find the underlying cause (5 Whys, fishbone) |
| **Sensitivity analysis** | Identify the variables with the most impact (tornado) |
| **Simulation** | Model combined effects of uncertainty (Monte Carlo) |
| **Stakeholder analysis** | Understand stakeholders' interests and influence |
| **SWOT analysis** | Strengths, weaknesses (internal), opportunities, threats (external) |
| **Trend analysis** | Is performance improving or deteriorating over time? |
| **Value stream mapping** | Visualise the flow of value and waste |
| **Variance analysis** | Determine cause and degree of difference between plan and actual |
| **What-if scenario analysis** | Assess the effect of scenarios on objectives |

### Estimating

Affinity grouping, analogous, function point (software size measurement), multipoint (three-point) estimating, parametric, relative estimating (story points), single-point estimating, story point estimating, wideband Delphi (planning poker), bottom-up.

### Meetings and events

| Event | Purpose |
|---|---|
| **Backlog refinement** | Clarify, split, estimate and order backlog items |
| **Bidder conference** | Give all prospective sellers the same information |
| **Change control board meeting** | Decide on change requests |
| **Daily stand-up** | Synchronise and identify impediments (15 min) |
| **Iteration planning / review / retrospective** | Plan the iteration; demonstrate the increment; improve the process |
| **Kickoff** | Launch the project/phase; align on objectives and roles |
| **Lessons learned meeting** | Capture knowledge to improve current and future projects |
| **Planning meeting** | Create, elaborate or review a plan and gain commitment |
| **Project review / phase gate** | Assess status and decide whether to continue |
| **Release planning** | Set the high-level plan for releases |
| **Risk review** | Analyse status of existing risks, identify new ones |
| **Status meeting** | Exchange and analyse progress information |
| **Steering committee** | Senior direction and decisions |
| **Wrap-up / close-out** | Obtain final acceptance, close the project |

### Other methods

Impact mapping (goals → actors → impacts → deliverables), modelling (prototypes, simulations), net promoter score (customer loyalty: % promoters − % detractors), prioritisation schema (MoSCoW, Kano, WSJF), timeboxing, design thinking (empathise, define, ideate, prototype, test), retrospectives formats (start-stop-continue, sailboat, 4Ls), customer journey mapping, personas.

## 19.4 Quick "which artifact?" guide

| You need to… | Use… |
|---|---|
| Record a current problem and its owner | **Issue log** |
| Record an uncertain event | **Risk register** |
| Record something believed true for planning | **Assumption log** |
| Track all change requests and their status | **Change log** |
| Record decisions and their rationale | **Decision log** |
| See who does what on each activity | **RACI chart / RAM** |
| Link requirements to their source and tests | **Requirements traceability matrix** |
| See stakeholders' current vs desired engagement | **Stakeholder engagement assessment matrix** |
| Show the project's total scope as deliverables | **WBS** (predictive) / **product backlog, story map** (adaptive) |
| Describe each WBS element in detail | **WBS dictionary** |
| Show key dates to executives | **Milestone chart / roadmap** |
| Show remaining work in a sprint | **Burndown chart** |
| Show scope changes and progress together | **Burnup chart** |
| Detect bottlenecks in flow | **Cumulative flow diagram** |
| Show cumulative planned spending over time | **S-curve** (cost baseline) |
| Show the logical sequence and critical path | **Project schedule network diagram** |
| Formalise the team's values and agreements | **Team charter** |
| Prioritise threats by probability and impact | **Probability and impact matrix / heat map** |

%%QUESTIONS%%
@@
Which of the following is a model rather than a method or an artifact?
A) Tuckman ladder
B) Risk register
C) Planning poker
D) Burnup chart
= A
? A model is a thinking strategy that explains a phenomenon, such as team development. Planning poker is a method; the risk register and burnup chart are artifacts.

@@
A project manager needs a document that records decisions made, who made them and why, so the reasoning is not lost. Which artifact is most appropriate?
A) Decision log
B) Issue log
C) Assumption log
D) Change log
= A
? A decision log captures decisions and their rationale. Issue, assumption and change logs serve other purposes.

@@
Which method would best help a team decide whether to develop a component in-house or purchase it?
A) Make-or-buy analysis
B) Value stream mapping
C) Net promoter score
D) Affinity grouping
= A
? Make-or-buy analysis compares the costs, risks and benefits of internal development versus purchase.

@@
Which visual artifact plots cumulative planned cost over time and typically has a characteristic shape?
A) S-curve
B) Histogram
C) Pareto chart
D) Tornado diagram
= A
? The time-phased cost baseline, plotted cumulatively, typically forms an S-curve.

@@
A team wants to visualise each step of its delivery process, including waiting times between steps, to eliminate waste. Which method fits best?
A) Value stream mapping
B) SWOT analysis
C) Regression analysis
D) Bidder conference
= A
? Value stream mapping shows value-adding and non-value-adding time across the whole flow, highlighting waste such as waiting.

Net promoter score is best used to measure:
A) Customer loyalty and willingness to recommend
B) The schedule performance index
C) Team velocity
D) The number of defects found in each release of the product
= A
? NPS subtracts the percentage of detractors from the percentage of promoters, measuring customer loyalty.
